Part 1: GitHub Basics

GitHub is a platform for storing, tracking, and collaborating on files using Git, a version control system. Think of it as “Track Changes” for everything — not just Word documents.

1.1

Repositories (Repos)

A repository is a project folder hosted on GitHub. It contains all of your project files plus the complete history of changes made to each file.

Finance analogy: A repo is like a shared drive folder for your annual budget — but one that remembers every draft, every edit, and who made each change.
Creating a new repo from the command line
git init my-budget-project
cd my-budget-project
git remote add origin https://github.com/your-org/my-budget-project.git
1.2

Commits

A commit is a snapshot of your files at a point in time. Each commit has a message describing what changed.

Finance analogy: Each commit is like a journal entry in your general ledger — a permanent record of a specific transaction (change) with a description.
Making a commit
# Stage changes
git add q3-forecast.xlsx

# Commit with a descriptive message
git commit -m "Update Q3 forecast with revised revenue projections"
1.3

Branches

A branch lets you work on a separate copy of the project without affecting the main version. When you’re done, you merge your branch back in.

Finance analogy: Branches are like creating a “what-if” scenario in your financial model. You explore a different assumption set without touching the approved baseline.
Working with branches
# Create and switch to a new branch
git checkout -b feature/new-pricing-model

# Do your work, commit, then merge back
git checkout main
git merge feature/new-pricing-model
1.4

Pull Requests (PRs)

A pull request is a proposal to merge changes from one branch into another. Team members review the changes, leave comments, and approve before the merge happens.

Finance analogy: A PR is like submitting a budget amendment for approval. Stakeholders review the line items, ask questions, request adjustments, and then sign off.
Creating a PR with the GitHub CLI
gh pr create \
  --title "Add Q4 expense projections" \
  --body "Includes updated headcount costs and software licenses."
1.5

Issues

Issues are used to track bugs, feature requests, and tasks. They can be assigned, labeled, and linked to pull requests.

Finance analogy: Issues are like line items on an action-item list from your monthly finance meeting — tracked, assigned, and closed when resolved.
Creating an issue from the CLI
gh issue create \
  --title "Discrepancy in March payroll report" \
  --body "Row 42 shows duplicate entry for contractor payment." \
  --label "bug,finance"

Part 2: Claude Code Basics

Claude Code is Anthropic's AI-powered coding assistant that runs in your terminal. It can read your files, write code, run commands, and help you build things — all through natural language.

2.1

What Is Claude Code?

Claude Code is a CLI (command-line interface) tool that brings the power of Claude, Anthropic's AI, directly into your development workflow. You type what you want in plain English, and Claude Code reads your project, writes or edits files, and runs commands.

📂
Reads your codebase

Understands your project structure, files, and context.

✏️
Writes & edits files

Creates new files or modifies existing ones based on your instructions.

▶️
Runs commands

Executes shell commands, installs packages, runs scripts, and more.

🔀
Works with Git

Commits changes, creates branches, and manages pull requests.

2.2

Getting Started

Install Claude Code
# Install globally via npm
npm install -g @anthropic-ai/claude-code

# Navigate to your project
cd my-budget-project

# Launch Claude Code
claude

Once launched, you're in an interactive session. Just type what you want Claude to do in plain English.

Example: asking Claude Code to help
> Read the CSV file in /data/expenses.csv and summarize
  the top 5 expense categories by total amount.

Claude Code will:
  1. Read the file
  2. Parse the CSV
  3. Calculate totals by category
  4. Print a summary for you
2.3

Essential Commands & Patterns

You Type What Happens
claude Starts an interactive session in the current directory
/help Shows available slash commands and usage tips
/commit Stages and commits your changes with an AI-generated message
Escape key Cancels the current operation
# prompt Use the CLAUDE.md file to give Claude project context
Tip: Create a CLAUDE.md file in your project root to give Claude Code persistent context about your project. For example: “This repo contains monthly financial reports in CSV format. The fiscal year starts April 1.”
2.4

Claude Code + Git Integration

Claude Code works seamlessly with Git. You can ask it to handle your entire Git workflow in plain language.

Git operations via Claude Code
> Create a new branch called "feature/q4-budget-updates",
  add the changes I just made, and commit with a descriptive message.

> Show me what changed since the last commit.

> Create a pull request with a summary of all the changes
  on this branch.

Part 3: Real Finance Workflows

Here are practical scenarios showing how a finance manager at a small software company can combine GitHub and Claude Code to work smarter.

Workflow 1

Automated Expense Report Generation

Scenario: Every month you export expense data from your accounting tool as a CSV. You need to categorize, summarize, and produce a PDF report for leadership.

1
Store your data in a GitHub repo

Create a repo called finance-reports and push your CSV files there each month.

2
Ask Claude Code to build the script 
> Write a Python script that reads data/expenses-2026-01.csv,
  groups expenses by category, calculates totals and percentages,
  and outputs a formatted markdown summary report.
3
Review, commit, and reuse

Claude Code generates the script. Review it, commit via /commit, and reuse it every month with new data.

Workflow 2

Budget vs. Actuals Tracking

Scenario: You maintain a budget spreadsheet and want to track how actuals compare over time with full version history.

1
Version your budget as CSV/JSON

Store budget data in a machine-readable format in Git so every change is tracked.

2
Use Claude Code for variance analysis 
> Compare budget.csv and actuals-jan.csv. Show me every
  line item where actuals exceed budget by more than 10%.
  Format the output as a table.
3
Track changes via pull requests

When updating the budget, create a branch, make changes, and submit a PR. Stakeholders review and approve before merge.

Workflow 3

Vendor Contract & License Management

Scenario: Your company uses dozens of SaaS tools. You need to track renewal dates, costs, and license counts.

1
Maintain a vendor registry in Git

Keep a vendors.json file with vendor name, cost, renewal date, and license count.

2
Ask Claude Code for renewal alerts 
> Read vendors.json and list all vendors with renewal dates
  in the next 60 days. Include the annual cost and flag
  anything over $10,000 for renegotiation review.
3
Automate with GitHub Actions

Set up a GitHub Action that runs the renewal check script weekly and opens an issue when renewals are approaching.

Workflow 4

Financial Dashboard Prototyping

Scenario: You want a simple internal dashboard to visualize monthly revenue, burn rate, and runway — without waiting for the engineering team.

1
Describe what you need to Claude Code 
> Build an HTML dashboard that reads data from
  financials.json and displays:
  - Monthly revenue bar chart
  - Burn rate trend line
  - Runway calculation (cash / avg monthly burn)
  Use Chart.js for the visualizations.
2
Iterate with Claude Code

Ask Claude to refine colors, add filters, or include new metrics. Each change is a new commit.

3
Deploy via GitHub Pages

Push to GitHub and enable Pages for free hosting. Your dashboard is live at your-org.github.io/finance-dashboard.

Best Practices for Finance Managers

DO

Use private repositories

Financial data is sensitive. Always use private repos and restrict access to authorized team members.

DO

Write descriptive commit messages

Future you (and auditors) will thank you. “Update Q3 forecast with revised SaaS revenue” beats “changes”.

DO

Use branches for budget iterations

Keep the approved budget on main. Explore changes on branches and merge only after approval.

DO

Create a CLAUDE.md file

Give Claude Code context about your project so it gives better, more relevant answers every session.

DON'T

Commit secrets or credentials

Never put API keys, passwords, or tokens in your repo. Use a .gitignore file and environment variables.

DON'T

Store raw PII in repos

Employee SSNs, bank accounts, etc. should not be in Git. Use anonymized or aggregated data instead.

DON'T

Skip code review on scripts

Even if Claude Code wrote the script, have someone review it via a PR before running it on real financial data.

DON'T

Blindly trust AI output

Always verify calculations and summaries against source data. AI is a powerful assistant, not a replacement for diligence.

Glossary

CLI
Command Line Interface — a text-based way to interact with your computer. Claude Code runs in a CLI.
Git
A distributed version control system that tracks changes to files over time.
GitHub
A cloud platform built on Git for hosting repositories and collaborating with others.
GitHub Actions
An automation feature in GitHub that can run scripts on a schedule or in response to events like pushes or PRs.
GitHub Pages
Free static website hosting from a GitHub repository. Great for dashboards and documentation.
Claude Code
Anthropic's AI coding assistant that runs in the terminal and helps with code, data, and automation tasks.
CLAUDE.md
A markdown file in your project root that gives Claude Code persistent context about the project.
PR (Pull Request)
A request to merge changes from one branch into another, with review and approval workflow.
.gitignore
A file that tells Git which files or directories to exclude from version control (e.g., credentials, large binaries).
npm
Node Package Manager — used to install JavaScript tools and libraries, including Claude Code.
